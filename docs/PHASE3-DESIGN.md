# Phase 3 Design — VGA Text Console + PS/2 Keyboard

NeutrinoOS Phase 3 adds a kernel-hosted VGA text console (`/dev/vga0`) and
a PS/2 keyboard driver, with the Console Abstraction Layer (CAL) routing
output to both consoles and automatically following whichever console
received input last.

Everything is implemented in C# inside the kernel (`src/kernel`); no C or
C++ sources are added. This document describes the design and the
hardware-contract details that were verified against QEMU.

## 1. Components

| File | Purpose |
|------|---------|
| `src/kernel/Platform/Vga/VgaTextDriver.cs` | VGA hardware driver: mode programming, text buffer access, cursor, scroll, fonts, palette |
| `src/kernel/Platform/Vga/VgaConsoleDevice.cs` | `IConsoleDevice` implementation for `/dev/vga0`: ANSI parser, CP437 mapping, line-discipline integration |
| `src/kernel/Platform/Vga/VgaFontData.cs` | Standard CP437 8x16 / 8x8 fonts (generated by `build/gen-vga-font.py` from the SeaBIOS VGA BIOS ROM) |
| `src/kernel/Platform/Ps2/Ps2Keyboard.cs` | 8042 controller bring-up, IRQ1 handler, scancode-set-1 decoder, ANSI byte synthesis |
| `src/kernel/Platform/Consoles/ConsoleAbstractionLayer.cs` | Registers `/dev/vga0` and `/dev/ttyS0`, echo sink, active-input switching |
| `src/kernel/Platform/Serial/LineDiscipline.cs` | Shared line editing (echo, backspace, history, Ctrl+C) for serial and keyboard bytes |

## 2. VGA text buffer layout and register usage

* Text buffer: physical `0xB8000` (identity-mapped 0–4 GB), 80×2 bytes per
  row, character byte + attribute byte per cell.
* Modes: 80×25 (8×16 font, mode-3-compatible register set) and 80×50
  (8×8 font; CRTC max-scan 7, sequencer map A selects the 8×8 font).
* Register programming (`ProgramTextMode`): MISC output, sequencer
  (SR0..SR4), full CRTC table (CR0..CR18), graphics controller (GR0..GR8),
  attribute controller (palette + mode), plus the Bochs VBE disable
  (`0x1CE/0x1CF`) so a firmware GOP mode left active by OVMF is turned off.
* Hardware cursor: CRTC registers 0x0E/0x0F; 80×50 uses scan lines 6–7
  of the 8-line cell.
* Scrolling: `ScrollUp` shifts rows 1..N-1 up by one row and blanks the
  last row (character+attribute pairs).
* Display geometry is 720×400 pixels (VGA mode-3 style; 80 × 9 pixel
  character cells in 9-dot clocking mode as programmed by SR1=0x00).

### Hardware-contract details verified during bring-up

These were established by testing (and by reading QEMU's `vga.c`):

1. **Attribute-controller port protocol.** Port `0x3C0` alternates
   INDEX/DATA writes; every palette entry must be written as an explicit
   index/data pair after a `0x3DA` read resets the flip-flop. Writing bare
   palette values desynchronizes the flip-flop and corrupts the palette
   (e.g. the background color).
2. **Color plane enable (AR 0x12).** The VGA BIOS always programs
   `0x12 = 0x0F`; the reset value zeroes all attribute color bits, which
   renders text black-on-black. The driver programs `0x12=0x0F` and
   `0x13=0x08`.
3. **DAC palette.** The first 16 DAC entries are programmed with the
   standard EGA/VGA colors because firmware may leave a custom palette
   (from a GOP graphics mode) in place.
4. **Font plane.** Under OVMF there is no legacy option-ROM execution
   (no CSM), so nothing populates VGA plane 2 with a font and the adapter
   renders blank glyphs. The kernel therefore loads the CP437 fonts
   itself using the classic INT 10h AH=11h sequence: synchronous reset,
   map mask = plane 2, odd/even addressing off, bytes written through the
   `0xA0000` window, then the text-mode state restored.
5. **Font storage layout.** Fonts live at plane-2 "window offsets"; the
   renderer (and the real hardware) expects **32 bytes per character**
   (scanline *i* of character *ch* at window byte `32*ch + i`) - the
   layout the VGA BIOS uses. The window is dword-addressed: window byte
   `K` lands in the plane-2 byte of video-memory dword `K`.
6. **Character-map select (SR3).** The 8×8 font for the 80×50 mode is
   loaded at the candidate plane-2 bases (0x2000/0x4000/0x8000 dwords)
   and the sequencer's character-map select is set to value 2; this maps
   to window offset 0x8000 in QEMU's model
   (`offset = (((sr3 >> 4) & 1) | ((sr3 << 1) & 6)) * 8192 * 4 + 2`).
7. **Font source.** `VgaFontData.cs` is generated from
   `/usr/share/seabios/vgabios-stdvga.bin` (the SeaBIOS VGA BIOS ROM
   shipped with QEMU) by `build/gen-vga-font.py`. The fonts are embedded
   as string-literal chunks (one char per font byte) because the kernel
   compiler (bflat/ILC kernel mode) cannot codegen large `byte[]` array
   initializers. Regenerate with `python3 build/gen-vga-font.py`.

## 3. ANSI terminal emulator

`VgaConsoleDevice` implements a subset of ANSI/VT100 sufficient for the
kernel shell and JIT applications:

* CSI parsing state machine: ground → after-ESC → inside-CSI, with
  numeric parameters (`_param0.._param3`), `?`/`>`/`<` private-marker
  swallowing, and bounded parameter accumulation.
* SGR (`ESC[...m`): reset, bold/bright foreground (attribute bit 3),
  reverse video, foreground colors 30–37 (plus 90–97 bright), background
  colors 40–47, reset-colors on 39/49.
* Clear operations: ED (0/1/2), EL (0/1/2).
* Cursor addressing/moves: CUP/HVP, CUU/CUD/CUF/CUB, GOTO column (G),
  save/restore cursor (ESC 7 / ESC 8), home.
* CR/LF/BS/TAB handled as raw console actions; other control characters
  are swallowed.
* Unicode → CP437 mapping for the box-drawing block and common
  punctuation (single/double frames, degree, plus-minus, middle dot,
  non-breaking space); characters < 0x100 are passed through as CP437
  codes directly.

## 4. PS/2 keyboard

* 8042 bring-up: disable both ports, drain the output buffer, read and
  rewrite the configuration byte (translation on, IRQ1 enabled, clock
  enabled), re-enable the keyboard port, reset the device (`0xFF`),
  drain responses, then enable the keyboard.
* IRQ1 → vector 33 via `Arch.RegisterHandler` and
  `IOAPIC.UnmaskIrq(1)`.
* Scancode-set-1 decoder with extended (0xE0) and Pause (0xE1) handling,
  Shift/Ctrl/Alt/CapsLock modifier tracking, and an LED update command
  (`0xED`) on Caps Lock changes.
* Keys are synthesized into the same ANSI byte stream the serial line
  discipline consumes (printable characters, `\b`/`\r`/`\t`, arrows as
  `ESC[A`..`ESC[D`, Home/End, Ins/Del/PgUp/PgDn, F1–F12) and delivered
  via `LineDiscipline.FeedByte`, so echo, editing, history and Ctrl+C
  behave identically on both consoles.

## 5. CAL multiplexer and active-input switching

* `ConsoleAbstractionLayer.Initialize` registers `/dev/ttyS0`
  (`SerialConsoleDevice`) and, unless the `console-vga-off` marker file
  is present, `/dev/vga0` (`VgaConsoleDevice`).
* Output fans out to every registered device (multiplexer loop over an
  interface-typed device list).
* The CAL installs a line-discipline **echo sink** so echo bytes are
  mirrored to both consoles; without it echo goes to the UART only.
* The UART RX consumer and the keyboard consumer mark their console as
  the active input device; `ConsoleMultiplexer.ActiveInput` therefore
  follows whichever console received the most recent input.

### Boot parameters (marker files)

NeutrinoOS has no command line; boot parameters are marker files on the
boot volume:

| Marker | Effect |
|--------|--------|
| `console-vga-off` | Do not initialize/register the VGA console (serial-only boot) |
| `console-vga-80x50` | Select 80×50 text mode with the 8×8 font |
| `console-active-vga` | Make VGA the initial active input device |
| `skip-echo` | Do not install the dual-console echo sink |
| `skip-ps2` | Do not initialize the PS/2 keyboard |
| `skip-vga-register` | Bring up VGA hardware but do not register the device |
| `skip-preempt` | Disable preemptive scheduling (debug) |
| `run-vga-test` | Run `vga_test.dll` after init (acceptance test) |
| `run-keyboard-test` | Run the interactive `keyboard_test.dll` |

## 6. Kernel integration order

1. Early boot: UART initialized for polled output; all boot logging via
   `DebugConsole` → UART until the CAL exists.
2. `Scheduler.EnableScheduling()` (skippable with `skip-preempt`).
3. `ConsoleAbstractionLayer.Initialize()`:
   a. create + register `/dev/ttyS0`, set it active,
   b. route UART RX into the line discipline, enable RX interrupts,
   c. `InitializeVgaConsole()` (unless `console-vga-off`): program the
      VGA mode, load fonts, register `/dev/vga0`,
   d. install the echo sink and initialize the PS/2 keyboard when the
      VGA device is present.
4. `[OK] Kernel initialization complete` + shell prompt — from here all
   output flows through the CAL to both consoles, and input arrives from
   both the UART (IRQ4) and the keyboard (IRQ1).

## 7. Interface-dispatch correctness notes (kernel runtime)

Phase 3 is the first configuration in which more than one type implements
`IConsoleDevice`. That turned two latent kernel-runtime bugs into boot
failures; both were fixed in this phase and are important invariants:

1. **`RhpResolveInterfaceMethod` / `GetInterfaceMethod` /
   `GetInterfaceMethodSlot` must never call `DebugConsole`.** The console
   multiplexer itself performs interface calls, so logging from the
   resolver re-enters the console, which re-enters the resolver ->
   unbounded recursion. (Previously unreachable because with a single
   `IConsoleDevice` implementation every call site was devirtualized at
   compile time.)
2. **`RhpInitialDynamicInterfaceDispatch` (native.asm) must keep the
   x64 ABI stack alignment**: six register pushes leave RSP ≡ 8 (mod 16),
   so the resolver call reserves 40 bytes (32 shadow + 8 padding).
   Violating this faults on aligned SSE spills inside the resolver.

## 8. Known limitations

* Text mode only: no graphics modes, no VBE/VESA, no framebuffer, no
  mouse, no window manager (Phase 3 scope).
* Single VGA console; no TTY multiplexing / virtual terminals.
* CP437 glyph set only, with a small Unicode→CP437 map for box drawing.
* US keyboard layout only; no key repeat configuration (the 8042 powers
  up with repeat enabled; typematic rate remains at the firmware default).
* VirtualBox: the default VMSVGA controller does not expose the legacy
  `0xB8000` text framebuffer; use the **VBoxVGA** controller (see
  `docs/PHASE3-ACCEPTANCE.md`). QEMU (`-vga std`) is the reference
  platform and is fully verified.
* The VGA font tables are loaded once at initialization from embedded
  font data; no runtime font upload ("load font" INT 10h calls are not
  emulated for user code).
