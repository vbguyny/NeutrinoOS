M3 step 2: async RequestDelegate + korlib async/sequence fixes, JITTest visibility (v0.1.217)

Async RequestDelegate (the Kestrel-shaped delegate Task RequestHandlerAsync):
- HttpContext.cs: RequestHandlerAsync delegate + IHttpRequestFeature unchanged;
  WebApplication gains Map* overloads for async handlers.
- WebHost: runs the handler; when it suspends, the returned Task + response are
  stored on the connection slot and the deferred response is written on a
  later service tick once the task completes (resume runs the state-machine
  continuation inline at the completing call).
- TasksWebApp: /api/v1/wait (suspends on a signal) + /api/v1/poke (completes
  it) demonstrate the deferred-response path.
- build/m3-http-check.py grows an "async" mode: two raw connections -
  wait on one, poke on the other - both responses checked. webapi-probe
  now runs 32 checks.

korlib runtime fixes (all found by making JITTest honest):
- AsyncTaskMethodBuilder/<T>: AwaitOnCompleted/AwaitUnsafeOnCompleted boxed
  the state machine BEFORE the task was materialized, so builder.Task read
  after Start() was a different instance than the one the boxed builder
  completed at SetResult - a suspended async Task method never completed its
  caller-visible task (this broke the whole async-RequestDelegate feature
  until fixed). The builders force the task into existence before boxing;
  AsyncValueTaskMethodBuilder<TResult>.SetResult also completes the backing
  task when it was materialized.
- ReadOnlySequence<T>: Slice/TryGet recovered segments via object->
  ReadOnlySequenceSegment<T> casts; Tier-0 fails EVERY coercion shape
  (as/castclass/is - probed on-device). They now recover segments by
  reference identity against the chain (FindByIdentity); Slice(long,long)
  walks the typed segment chain directly (no positions).
- ReadOnlySequence<T>.Enumerator: the ctor took the whole ~48-byte sequence
  by value (garbled: enumeration yielded nothing) and its six-arg
  replacement faulted outright (j .Enumerator..ctor +0x4A cr2=0 in the
  AppTest echo); GetEnumerator now builds the enumerator by direct field
  stores.

JITTest honesty + coverage:
- RunCategory printed errors via Debug.Write (compiled out of default
  builds) - category aborts were silent; it now reports + records them, and
  MemoryPipelineTests.RunAll wraps each test in RunStep so one throwing test
  no longer kills the category. This exposed that Memory/Pipelines has been
  silently aborting at its ReadOnlySequence test since M2 - the Pipe tests
  had never run.
- Fixed the sequence test's segment chaining (RunningIndex contract);
  added TestTaskSuspension (first on-device test of a Task that suspends and
  completes later - the async-delegate pattern) and a ValueTask large-struct
  probe (currently RED - see below). Boot is now 3016 passed / 7 FAILED
  (previously a silent 3005/0): category/Overflow NRE, vt-large-struct-probe
  NRE, readonly-sequence slice-enumeration NRE, pipe-read-wake
  InvalidOperationException, pipe-pump-1mb NRE, pipe-async-sync, and the
  read-async-status record. Root thread: ValueTask<TResult>/Task<TResult>
  with a large TResult (~48-byte ReadResult) misbehave on Tier-0 - next
  korlib work item before the pipe tests can go green (documented in
  docs/KESTREL-PORT.md).
